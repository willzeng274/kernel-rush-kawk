# Isolated triple-context prototype on exact 87

Prepared and CPU-checked; **not compiled, GPU-tested, submitted, or rebased onto 89/90**. Candidate: `work/candidates/krxfty_triple_context/engine`. Every baseline file matches commit `9719c8ba764766223fdcdd9803d06f66a4c9a32a`. Only `engine.py`, `recycle.py`, and `pair_cache.py` differ; the other 15 files are byte-identical. Model computations, prompt-model seeds, exact greedy acceptance, pacing, geometry, M64 selection and existing pair behavior are retained.

Each sequence owns 4096 additional slots. An exact 96-bit tag comprises oldest-token int32 plus tail-pair int64. Current-prompt observations seed newest distinct successors, at most 8 per context; collisions keep the newest context. Invalid tags are reset each request. Draft precedence is valid host spine, exact triple at the requested rank, exact pair at that rank, then unigram. Missing ranks fall through. The existing publisher launch also publishes triple entries only for consumed root/accepted rows, chronologically; later consumed collisions win. There is no additional per-round kernel launch.

For a root ending `(x,y,z)`, saved root state is oldest=`x`, pair=`(y,z)`. A child `c` saves oldest=`y`, pair=`(z,c)`, using its parent's saved pair, irrespective of sibling layout or spine replacement. After acceptance, the final consumed row supplies predecessor=`row token` and previous predecessor=`high32(saved pair)`, while unchanged acceptance supplies the new root prediction. Zero matched drafts uses row 0; frozen `path_len=-1` writes neither predecessor. A one-token prompt initially disables root triple lookup, while its children already have three tokens of context. Tests reconstruct these values independently from full histories and parent ancestry.

`CPU_RESULTS.json` records 168 prompt cases, 1603 host/device-hash cases, 21,852 ancestry checks and 17 complete/reused requests across T1–4/12 and B1/2/4/16. The 368 simulated rounds include zero/full/partial/frozen paths. Directed checks cover duplicate root children choosing alternate longest path `[4,6]`, clipped progress retaining `[1]`, both tag-component collisions, missing-rank fallback, spine priority, empty-seed reset, and a real full-history collision whose last consumed context wins. Six broken variants were detected: either tag comparison removed, child-oldest corruption, root-oldest corruption, unaccepted publication, and missing final drain.

The queued-stream simulation reaches two in-flight rounds, tracks pinned-buffer aliases, and checks cancellation/reuse at three yield positions, seed-construction failure drain, first-token fencing, and sticky rejection after failed drain. This establishes behavior in the simulator, not CUDA ordering.

`HOST_LAUNCH_CHECKS.json` executes actual constructors and launch wrappers for 96 combinations including T1–4/512/5000. Baseline buffer shapes/controllers remain equal; triple buffers, pointer order, types, grids and constexprs are checked. Unchanged `(S,MAXA,SP)` for R2/3/4/8/16/32/42/64 respectively: `(1,1,3)`, `(2,2,5)`, `(3,3,7)`, `(4,4,9)`, `(5,5,11)`, `(6,6,13)`, `(7,7,15)`, `(8,8,17)`.

The new device cache costs 176 KiB/sequence; maximum sparse staging adds 208 KiB/device and 208 KiB/pinned-host per sequence, plus 4BR+4B bytes of context state. Prompt scanning, four bounded uploads and three index copies add first-token work. Per-node hashes, dependent loads and register pressure may outweigh increased specificity; no acceptance or speed improvement is established. This broadens non-spine branches and publishes before the next device round, whereas host n-grams affect the lagging spine only.

No B sweep or invented alignment variants. Inspect resources/spills and lane predicates.
